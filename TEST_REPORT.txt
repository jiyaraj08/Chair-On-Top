D. KNOWN LIMITATIONS
  1. Phones (under 600px wide): each card shows Like and Save only; Share and Download are inside
     the photo viewer. Four buttons do not fit in a ~130px card without shrinking below a
     comfortable touch size. From 600px up, all four show on the card.
  2. Photos are single full-size JPEGs (about 100-170 KB each). No smaller versions exist, so
     "responsive image sizing" is CSS sizing + width/height attributes only. Real thumbnails
     would need new image files (a separate step).
  3. Alt text on Load More cards omits "of 16" (see test 3).
  4. No editorial titles: cards show the style name and "Image N" (a display label only).
  5. The results page's own search box has no live suggestions; the header panel does.
  6. Suggestion counts ("64 photographs") are shown exactly as /api/search/suggestions returns them;
     I did not change or re-derive the backend numbers.
  7. Without JavaScript on a narrow screen the whole menu shows stacked and covers the top of the
     page. That is how your original header already behaved (I measured it); I did not change it.
  8. Viewer counter says "Result 3 of 64" (position in the search), the caption says "Japandi - Image 5".
  9. routes/pages.py has an unused broken import (from app.config). Left alone.
